## 这一版做的是「做完的东西能带走」

v1.1.5 解决了"从看到做"，v1.1.6 补的是后半段：配完的配置能存成文件、看过的东西找得回来、
导入的内容知道是谁给的。

## 配置能导成文件了

以前只有「复制」。要存档、要发给别人、要当设备启动配置用，都没辙。

| 你要干什么 | 用哪个 | `system-view` |
|---|---|---|
| 粘进 eNSP / 真机的命令行 | 复制 | **保留** |
| 存成文件、当启动配置加载 | 导出 `.cfg` | **去掉** |

差别只有一行，但写错了两边都不通 —— 命令行下没有 `system-view` 进不了系统视图，
配置文件里留它又等于一条无效命令。所以导出的内容单独走 `assets/exportcfg.js`，命令行能直接测。

- 片段、实验、预设、单设备剧本：一个按钮存成文件，文件名就是标题。
- **任务按设备各导一份**：三台设备三个文件，不会混在一起。
- 非网络内容按语言给扩展名：`.sql` / `.py` / `.sh` / `.txt`。
- 桌面版弹「另存为」；取消就明确说取消。

## 最近打开

左轨的时钟图标：最近 20 条，后进先出，重复打开只提到最前。点开一条仍留在「最近」里。

## 知道内容是哪儿来的

导入的内容在卡片标题后面有个灰色「导入」小标，悬停显示包名和版本。内置内容不标记。

## 顺手挖出来的三个真 bug

都是「看着正常、其实没生效」那类：

| 问题 | 后果 | 现在 |
|---|---|---|
| 桌面版不设保存路径，Chromium 直接判 `cancelled` | **「导出全量 JSON」一直在弹成功，磁盘上什么都没写** | 主进程接管 `will-download`，正常弹另存为并回报结果 |
| `collectIds()` 只认 `categories`，已装的包用的是 `cats` | 已装包的 id 查重失效，第二个包能撞第一个包的片段 id | 两个都认 |
| 分类按难度分组时，没写 `level` 的条目掉进分组缝 | 导入的片段在列表上**一条都看不见**，看着像导入失败 | 单独归一组「未分级」 |

第一条从 v1.0 起就存在，只是没人去下载目录里确认过。这也是这次特意跑了一遍真机路径
（启动 → 点导出 → 去下载目录看文件 → 读文件内容）才发现的。

## 新增自检

```bash
node _dev/check-export.js    # 40 条：扩展名 / 文件名 / 整形 / 两种模式 / 按设备切开
npm run check                # 现在串 8 个静态自检
npm run check:ui             # 7 项界面探针（导出预览 / 最近 / 来源标记 / 任务闭环）
```
